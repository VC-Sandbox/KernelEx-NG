# KernelEx-NG

KernelEx-NG is an add-on for **KernelEx on Windows 98 SE**. It adds a large part of the Windows Vista – Windows 10
programming interface (API), so that programs built for modern Windows can start on Windows 98. Examples are
Chromium-based browsers, Firefox and other Gecko browsers, and modern installers and runtimes.

> [!WARNING]
> **This entire project was generated by AI.**
> The person guiding the AI is doing this purely as a **proof of concept**. The questions are:
> - How far can AI get at reverse engineering?
> - How far can Windows 98 be pushed when an AI does the slow work of studying the Windows kernel and system DLLs?
>
> That person **does not endorse "vibe coding"** for serious projects or for programming in general.
> This project is **for learning only**: understanding Windows NT internals, reverse engineering and systems design.

> [!CAUTION]
> **Do not install this on a machine that holds important or personal data. Losing data is likely.**
> KernelEx-NG changes how Windows 98 runs programs, patches code in memory and can crash or freeze the whole
> system. Use it only in a **virtual machine** or on a spare computer with nothing on it that you need.
> Keep a backup or snapshot of the VM before installing.

## What it adds

KernelEx 4.5 already lets many Windows 2000/XP programs run on Windows 98. KernelEx-NG goes further, toward the
Windows 10 API level. It plugs into KernelEx as an extra *API library* (`kexnt.dll`) and adds:

- **NT 6+ / Windows 10 functions** in KERNEL32, NTDLL, ADVAPI32, USER32, GDI32 and more. Examples:
  - SRW locks, condition variables and `WaitOnAddress`
  - fiber local storage and vectored exception handling
  - a real-looking NT PEB and the native registry calls
  - named pipes, completion ports and job objects
  - shared memory with NT rules, and the thread-pool APIs
- **API-set DLLs** (`api-ms-win-*.dll`), generated from the real Windows 10 API-set tables.
- **Stub DLLs** for Windows libraries that do not exist on 98 (`dwmapi`, `bcrypt`, `winhttp`, `avrt`, ...). Each
  does the safe, documented "not available" thing, or a small real implementation.
- **Version profiles** (Windows 7 … Windows 11 / Server 2025) that you choose per program on the KernelEx tab.
- **Fixes for KernelEx 4.5 behaviour** that modern programs trip over. Examples: shared file locks for SQLite,
  `SwitchToThread`, Unicode INI files, layered windows, file dialogs.
- **Diagnostics built in:** a crash log, a hang dump, a sampling profiler and a test suite.
- **No effect on Windows 98 programs.** A program built for Windows 9x (PE subsystem 4.x) is sent to the normal
  KernelEx/Windows 98 code. Only programs built for NT 5+, or given an NT profile, use the new layer.

The full story of how each part works, and why it was built that way, is in the **[wiki](docs/wiki/Home.md)**.

## Requirements

**Target machine (Windows 98 side):**
- Windows 98 SE (4.10.2222), in a virtual machine (VMware, QEMU/KVM, 86Box) or on spare hardware.
- **KernelEx 4.5.2 installed first.** It is the base KernelEx-NG plugs into, and everything was tested with it.
  The source tree here is KernelEx 4.6.0 Beta 1 (by Ley0k). That version uses the same plugin interface, but
  KernelEx-NG has **not** been tested on an installed 4.6 beta. KEXSETUP's shared-memory enlargement only applies
  to KernelEx 4.5.x and is skipped (with a log line) on other versions.
- A CPU with SSE2 for modern browsers. KernelEx-NG itself also runs on CPUs without SSE.
- **AVX hidden from the guest.** Windows 98 cannot save AVX registers, and programs that use AVX will crash:
  - VMware: add `cpuid.1.ecx = "--00:----:----:----:---0:----:----:----"` to the `.vmx` file.
  - QEMU: use `-cpu max,-avx,-avx2,-fma,-f16c`.
- At least 512 MB RAM (1 GB recommended) and a fixed swap file of about 2000 MB.

**Build machine (Linux, or Windows with MSYS2):**

| Tool | Needed for | Notes |
|---|---|---|
| GNU make, Python 3 | everything | |
| **[llvm-mingw](https://github.com/mstorsjo/llvm-mingw)**, msvcrt flavour, i686 | everything (**recommended**) | tested with release 20250114; every test CD so far was built with it |
| *or* MinGW-w64 GCC | everything | Debian/Ubuntu: `sudo apt install gcc-mingw-w64-i686 g++-mingw-w64-i686 binutils-mingw-w64-i686` (tested with GCC 14). The stub DLLs still need llvm-mingw's import libraries, see below. GCC-built binaries have not been tested on Windows 98 yet |
| xorriso | the test CD image | optional; `tools/mkiso.py` is used when it is missing |
| llvm-mingw **ucrt** flavour | `ucrttest.exe` only | optional (`UCRT_CC=`) |
| Open Watcom 2 | rebuilding `KEXALIAS.VXD` | optional; a built copy is kept in `new_stubs/vxd_alias/` |
| Windows 98 SE CD DLLs | `make verify` (import check) | optional (`WIN98_DLLS=`) |

The original KernelEx parts (core, kexbases, kexbasen, VxD) are **not** rebuilt. They come from your KernelEx
install. Rebuilding them needs Visual C++ 6.0 (see `COMPILE.TXT` and `README.KernelEx.md`).

## Building

```bash
git clone <this repository> KernelEx-NG
cd KernelEx-NG/new_stubs
make CROSS=i686-w64-mingw32- iso
```

With **llvm-mingw**, put its `bin` folder first in `PATH`, for example
`export PATH=$HOME/llvm-mingw-20250114-msvcrt-ubuntu-20.04-x86_64/bin:$PATH`.

With **GCC**, also point `MINGW_LIBDIR` at llvm-mingw's i686 import libraries. Debian's MinGW import libraries
lack some newer Windows functions (for example `ProcessPrng`), and the stub generator reads each function's
argument size from them:

```bash
make CROSS=i686-w64-mingw32- MINGW_LIBDIR=$HOME/llvm-mingw-20250114-msvcrt-ubuntu-20.04-x86_64/i686-w64-mingw32/lib/ iso
```

Run `make clean` when you switch toolchains, because the table of function sizes is cached in `build/stubs/`.

The output goes to `new_stubs/build/`:

| File | What it is |
|---|---|
| `kexnt.dll` | the KernelEx-NG API library (the core of this project) |
| `kexver.dll` | version profiles (Windows 7 … 11) as a KernelEx API library |
| `api-ms-win-*.dll` | API-set forwarder DLLs |
| `build/stubs/*.dll` | stub DLLs for Windows libraries that 98 lacks |
| `kexsetup.exe` | installer / uninstaller |
| `kextest.exe`, `kexroute.exe`, `kexcfg.exe`, ... | tests and tools |
| `kexng.iso` | all of the above on one CD image, with `README.TXT` |

Useful options:
- `make check` lists the exports of every built DLL.
- `make verify WIN98_DLLS=<folder>` checks that every import exists on Windows 98 SE.
- `make WIN10_DLLS=<folder> iso` puts **your own** Windows 10 DLLs on a **private** test CD (see below).

The build refuses some mistakes by itself:
- `kexnt.dll` may import only KERNEL32 and ADVAPI32.
- `check_nosse.py` fails the build if SSE instructions slip into the binaries.

## Installing

1. **Back up / snapshot the VM.** (See the warning above.)
2. Install **KernelEx 4.5.2** and restart.
3. Copy everything from the CD (or `new_stubs/build/iso/`) to `C:\KEXTEST`.
4. Optional: add the Windows 10 DLLs described in the next section.
5. Run `C:\KEXTEST\KEXSETUP.EXE`, then **restart Windows**. KEXSETUP does the following:
   - copies `kexnt.dll` into the KernelEx folder and adds it to every configuration in `core.ini` (a backup is kept
     as `CORE.KNG`);
   - copies the API-set DLLs, and the stub DLLs where Windows has no DLL of that name, to `C:\WINDOWS\SYSTEM`;
   - adds the version profiles to the KernelEx tab;
   - writes its log to `kexsetup.log`.
6. Check it worked: run `KEXCFG.EXE` and `KEXTEST.EXE` (it writes `kextest.log`).

To pick a Windows version for a program: right-click it → **Properties** → **KernelEx** tab → "Use specific
compatibility mode" → for example *Windows 10 21H2*.

**Updating:** after every new build, copy the new files and run KEXSETUP again, then restart. KernelEx always loads
the installed copy of `kexnt.dll`, not the one next to the test tools.

**Uninstalling:** `KEXSETUP.EXE /u`, then restart.

### DLLs that are not included, and how to get them

KernelEx-NG **never redistributes Microsoft DLLs**. A few genuine Windows 10 DLLs make more programs work. You can
copy them from a Windows 10 or 11 installation **you own**. Always use the **32-bit** copies from
`C:\Windows\SysWOW64` (on 32-bit Windows: `C:\Windows\System32`).

| DLL | What needs it | Where to get it |
|---|---|---|
| `ucrtbase.dll` | every program built with Visual Studio 2015 or newer (the Universal C Runtime); also the VC++ 2015–2022 installer | Windows 10/11 `SysWOW64`, or the Windows 10 SDK: `Redist\ucrt\DLLs\x86\ucrtbase.dll` |
| `DWrite.dll` | DirectWrite text in Chromium browsers (better text rendering) | Windows 10/11 `SysWOW64` |
| `TextShaping.dll` | needed by that `DWrite.dll` | Windows 10/11 `SysWOW64` |

How to use them, either way works:
- **Install time:** make a folder `WIN10` next to `KEXSETUP.EXE` and put the DLLs in it, **or** put them next to it
  renamed to `*.W10` (for example `DWRITE.W10`). KEXSETUP copies them into `C:\WINDOWS\SYSTEM` and removes them
  again with `/u`.
- **Build time:** `make WIN10_DLLS=/path/to/folder iso` puts them on the CD in that form.
  **Such a CD is for your own use only. Do not share it.**

Do **not** copy Microsoft's own `api-ms-win-*.dll` files to Windows 98. KernelEx-NG builds its own.

Some programs also need older Microsoft runtimes, installed the normal way:
- Internet Explorer 6 SP1, which brings MSXML 3.0 for some installers
- DirectX 9.0c
- the matching Visual C++ redistributable
